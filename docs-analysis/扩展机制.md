## 1. 通用插件系统(主扩展点)

### 扩展点名称:Plugin(Host API 1.12.0)

- **接口/类型**:`PluginManifest`(`src/shared/plugins/plugin-manifest.ts`)、`PluginModule`(`activate(maestro: MaestroSdk)`)、`HOST_API` RPC 表(`src/shared/plugins/rpc-protocol.ts:26-73`)。
- **注册方式**:文件系统发现(插件目录)+ `plugin-manifest.json`;`PluginManager.refresh()`(`plugin-manager.ts:118-200`)。
- **加载时机**:启动 `pluginManager.refresh()` + 目录 hot-reload(150ms debounce,`plugin-manager.ts:55`)。
- **生命周期**:`PluginManager` 管理;tier-1 每插件一个 Electron `utilityProcess`(`plugin-sandbox-host.ts`);`BackgroundSupervisor` 重启。
- **可访问资源**:经 broker 授权的 capability(33 个,`permissions.ts:30-97`)与 scope(path/host/allowlist/none,`:145-188`)。
- **权限边界**:默认拒绝的 `PermissionBroker.authorize`(`permission-broker.ts:72-121`);ed25519 签名(`signing.ts`);sealed 授权账本 + 新鲜性锚 + tombstone(`authorization-ledger.ts`);act 动词(`agents:dispatch`/`process:spawn`)需精确 allowlist scope。
- **调用路径**:sandbox RPC → `plugin-host-handlers.ts` 实现(fs.read/net.fetch/agents.dispatch...,带大小上限与 real-path 再授权)。
- **示例实现**:first-party bridge(`first-party-bridge.ts`)把 Encore 特性(Pianola/Director's Notes/Coworking)作为「一方插件」暴露于扩展市场。
- **稳定性**:有 drift 测试守恒 SDK 与 host 契约;31+22 测试覆盖 rollback/tombstone/tamper/realm-escape/symlink/egress/scope-revoke/crash-restart。
- Evidence:如上文件 + `packages/plugin-sdk/src/index.ts`(1540 行,vendored)。

[Inference] 判据核验:① 可加新实现(是,manifest+entry);② 入口发现(是,文件系统+refresh);③ 调用方依赖抽象(是,`MaestroSdk` + capability);④ 生命周期明确(是,manager+supervisor);⑤ 错误隔离(是,进程隔离 + broker);⑥ 实际示例/测试(是,first-party + 53 测试文件)。→ **真实扩展系统**。

### 信任层与贡献类型

- 3 信任层:`plugin-manifest.ts:7-32`(tier0 数据贡献 / tier1 沙箱计算 / tier2 沙箱 UI)。
- 14 贡献类型:`contributions.ts:56-200`(themes/iconPacks/prompts/settings/commandMacros/cueTriggers/commands/panels/agents/tools/keybindings/uiItems/hostViews/groupings),ID 命名空间 `<pluginId>/<localId>`。

## 4. 扩展生命周期 / 权限边界 / 兼容性 / 测试 / 限制

- 生命周期:发现 → 签名验证 → tier 门控 → 账本授权 → sandbox 激活 → 后台监督;禁用→停工保授权,撤销→删授权停工(fail-closed)。
- 权限边界:broker 默认拒绝 + scope + 大小上限 + real-path 再授权 + egress guard;OS keyring 不可用时 **session-only fail-safe**(不持久化 trusted)。
- 兼容性:Host API 版本 1.12.0;SDK drift 测试;`HOST_API` 表为单一真相源。
- 测试:53 文件(31 main + 22 shared)。
- 限制:仅在 Encore `plugins` 开启时可用;vm realm 为 defense-in-depth(进程隔离才是承重边界);Cue 的 Debate/Auto Run edge 模式未实现。

## 已确认事实

- 存在真实安全硬化插件系统(3 层/33 能力/broker/签名/sealed 账本/沙箱)与 SDK。
- 领域扩展点:agent、Cue 事件/订阅/变量、prompt、主题、pipeline。
- Pianola/WebServer 为内部 DI,非公开扩展契约。

## 合理推断

- 「一方插件 bridge」既是扩展系统的首个真实示例,也是 Encore 特性的统一上架机制。

## Unknown 与待验证事项

- 第三方插件实际加载/签名体验(未运行外部插件)。
- keyring 不可用(headless Linux)时 session-only 模式的实际 UX。

## 批判性评估

- 插件系统设计严谨(进程隔离 + 多重授权 + drift 守恒),是仓库内安全工程化程度最高的子系统。
- vm realm 的「defense-in-depth」表述诚实,未夸大为主隔离。
